## 一、现有架构分析（与本功能相关组件）

| 层级 | 关键文件 | 作用 | 在本功能中的角色 |
|---|---|---|---|
| MCP Server | [mcp_servers/sqlserver_mcp_server.py](file:///c:/Users/GOBAO/Downloads/deer-flow/mcp_servers/sqlserver_mcp_server.py) | 只读 SELECT、`describe_table`、`health_check` | 直连 MES / WMS 数据库的基座 |
| MCP Server | [mcp_servers/rag_kb_server.py](file:///c:/Users/GOBAO/Downloads/deer-flow/mcp_servers/rag_kb_server.py) | pgvector 语义检索 `search_knowledge` / `expand_sources` | 沉淀 8D/FMEA/SOP/历史不良报告的领域知识库 |

| 后端网关 | `backend/app/gateway/`、`backend/app/channels/` | 会话与流式通道 | 无需改动，天然承载对话式分析 |

结论：对话式不良品分析可在**不修改现有 Python 代码**的前提下，通过"新增 1 个 Skill + 新增 1 个 API 类 MCP + 复用 SQL Server MCP + 注册配置"完成首版。

## 二、不良品分析数据流程设计

```
用户提问（自然语言）
   │
   ▼
defect-analyst Skill（意图识别 + 模板选择 + 硬约束）
   │   ├─ 指标：不良率 DPPM / Pareto / 8D 要素 / SPC 控制点
   │   ├─ 维度：工单、物料、工位、供应商、批次、时间、不良代码
   │   └─ 时段：日 / 周 / 月
   ▼
MCP 工具调用层（按数据源路由）
   ├─ sqlserver-mcp     → MES（工单/不良/工位）、WMS（IQC/批次/库位）
   ├─ erp-api-mcp       → ERP（物料主数据 / 供应商 / 采购批次 / BOM）
   └─ rag-kb（可选）    → 历史 8D 报告 / FMEA / SOP 语义检索
   ▼
Skill 侧聚合（JOIN 策略 + Pareto/SPC 计算模板）
   │   交叉口径：批次号 / 物料编码 / 工单号 作为跨源主键
   ▼
chart-visualization（可选，生成 Pareto / 趋势 / 堆叠图）
   ▼
结构化输出：口径 → Top 不良 → 趋势结论 → 下一步钻取建议
```

跨源关联主键（必须在口径对齐阶段确认）：
- `WorkOrderNo`（工单号）：MES ↔ ERP
- `MaterialCode`（物料编码）：MES ↔ ERP ↔ WMS
- `BatchNo / LotNo`（生产/来料批次）：MES ↔ WMS
- `SupplierCode`（供应商编码）：ERP ↔ WMS（IQC）

## 三、MCP 数据接入方案（混合：直连 + API）

### 3.1 直连类（MES / WMS → SQL Server）
- 直接复用 [mcp_servers/sqlserver_mcp_server.py](file:///c:/Users/GOBAO/Downloads/deer-flow/mcp_servers/sqlserver_mcp_server.py) 的 `execute_sql` / `describe_table`。
- 若 MES / WMS 与 sales 业务库是**同一实例不同库**：在 [extensions_config.json](file:///c:/Users/GOBAO/Downloads/deer-flow/extensions_config.json) 新增两条 mcpServers 实例，分别传入不同的 `SQLSERVER_DATABASE` 环境变量（`$SQLSERVER_MES_DATABASE`、`$SQLSERVER_WMS_DATABASE`），命名为 `sqlserver-mes` / `sqlserver-wms`。不改代码，仅通过 env 差异化。
- 若 MES / WMS 是**异构数据库**（MySQL/Oracle/达梦）：新增 `mcp_servers/mysql_mcp_server.py` 或 `oracle_mcp_server.py`（后续代码阶段再做，本轮不落地），接口签名对齐 `execute_sql` / `describe_table` / `health_check`，保持 Skill 层调用一致。

### 3.2 API 类（ERP → REST / iPaaS）
- 本轮不落地代码，规划新建：`mcp_servers/erp_defect_api_mcp_server.py`。
- 参照 [rag_kb_server.py](file:///c:/Users/GOBAO/Downloads/deer-flow/mcp_servers/rag_kb_server.py) 的 `urllib` 或改 `httpx` 封装 HTTP 调用，提供如下工具：
  - `list_materials(material_code: str | None, limit: int)` — 物料主数据
  - `list_suppliers(supplier_code: str | None)` — 供应商主数据
  - `list_purchase_batches(start_date, end_date, material_code | None)` — 采购批次/来料
  - `get_bom(product_code: str)` — BOM 展开
- 鉴权采用环境变量：`ERP_API_BASE_URL` / `ERP_API_TOKEN` / `ERP_API_TIMEOUT`；失败走与 sqlserver MCP 一致的 `{ok: false, error_type, error}` 返回结构。
- 在 `extensions_config.json` 以 `stdio` 类型挂载，保持全项目统一。

### 3.3 知识沉淀（可选增强）
- 将 8D 报告、FMEA、质量 SOP 通过 pgvector 索引写入 `rag_chunks` 表，`namespace=quality.cn`，`kb_id=defect_analysis`。Skill 可按需调用 `search_knowledge` 获取整改经验与典型失效机理。

## 四、Skill 落地规划：`skills/custom/defect-analyst/SKILL.md`（本轮仅产出设计稿，不创建文件）

**元信息**：`name: defect-analyst`，description 触发词：不良率 / 不良品 / DPPM / Pareto / 不良 TopN / SPC / 批次追溯 / 供应商不良 / 工位不良 / 不良趋势。

**硬规则（对齐 sqlserver-sales-analyst 范式）**：
1. 只读 SELECT；时间跨度建议 ≤ 90 天，超出需分段。
2. 优先使用内置模板；字段未知或报错时回退调 `describe_table`。
3. 跨源分析强制以批次号 / 物料编码 / 工单号作为主键。
4. 所有结论必须声明口径（时间窗、工厂、产线、过滤条件）。

**业务表结构（占位，第一阶段口径盘点后填实）**：
- MES：`dbo.MfgWorkOrder`、`dbo.MfgDefectRecord`、`dbo.MfgInspectionItem`、`dbo.MfgStation`
- WMS：`dbo.IqcInspection`、`dbo.InventoryBatch`
- ERP（API）：`materials`、`suppliers`、`purchase_batches`、`bom`

**必备分析模板（至少 8 个，电控行业通用）**：
1. 不良率 DPPM（日/周/月，产线）
2. Pareto — Top 不良现象 / Top 不良工位 / Top 不良物料
3. 供应商不良排行（IQC + 过程不良合并）
4. 批次追溯（给定成品批次 → 回溯原料批次 → 定位 IQC 与供应商）
5. 工单不良明细与 FPY（First Pass Yield）
6. 工位不良趋势（SPC 式按时间窗）
7. 物料-不良代码交叉热力（用于发现共性失效机理）
8. 返修 / 报废占比（区分可修 vs 报废）

**输出格式**：查询口径 → 关键指标 → Top 发现 → 趋势结论 → 钻取建议 → 可视化建议（交给 chart-visualization）。

## 六、风险与对策
- **跨源口径不一致**：Task 1 的字段字典为关键前置，必须业务签字。
- **ERP API 限流**：MCP 内置 `ERP_API_TIMEOUT` 与重试；在 Skill 层限制查询粒度（避免大范围批量拉取）。
- **SQL 注入与写操作**：沿用 sqlserver_mcp_server 的 `_validate_readonly_sql` 正则白名单，不放开任何写路径。
- **不良代码字典不统一**：在 Skill 内维护"不良代码映射表"，对 MES 原始代码做统一归类。
