# DeerFlow 权限控制落地方案（RBAC + ABAC）

本文给出一套可直接落地的权限控制设计，目标是让你建库后即可开始接入 `MyGuardrailProvider`。

方案基线：

- 规则存储：`Postgres`
- 身份来源：`JWT claims`（由 SSO 签发）
- 资源标识：`namespace + kb_id`（工具和 MCP 走统一 `resource_key`）
- 冲突策略：`默认拒绝 + deny 优先于 allow`

---

## 1. 设计目标

- **工具权限控制**：按部门、角色限制工具（`read_file`、`bash` 等）访问。
- **知识库权限控制**：按部门、角色限制知识库（`namespace/kb_id`）访问。
- **可扩展 ABAC**：支持时间窗、子代理限制、命令黑名单、路径白名单等条件。
- **可审计**：每次授权决策可追踪、可复盘。

---

## 2. 核心判定模型

### 2.1 统一资源命名

建议统一使用 `resource_key`，避免“同一个资源在不同模块命名不一致”。

- 工具：`tool:<tool_name>`，如 `tool:read_file`
- 知识库：`kb:<namespace>:<kb_id>`，如 `kb:corp.cn.finance:kb_invoice_001`
- MCP 工具：`mcp:<server>:<tool>`，如 `mcp:notion:query_database`

### 2.2 冲突处理规则（固定）

1. 查询所有命中的策略
2. 先匹配 `DENY`（按 `priority` 升序）
3. 再匹配 `ALLOW`（按 `priority` 升序）
4. 无命中时：`DENY`（默认拒绝）

---

## 3. 数据模型（用户/角色/部门/资源/策略）

### 3.1 组织与身份

- `departments`：部门（支持树形）
- `users`：用户（映射 JWT `sub`）
- `roles`：角色
- `user_roles`：用户角色关系

### 3.2 资源与策略

- `resources`：统一资源目录（TOOL/KB/MCP_TOOL）
- `policies`：授权策略（RBAC + ABAC）
- `authz_audit_logs`：授权审计日志

```sql
-- ============================================
-- 0) 清理（可选）
-- ============================================
drop table if exists authz_audit_logs;
drop table if exists policies;
drop table if exists resources;
drop table if exists user_roles;
drop table if exists roles;
drop table if exists users;
drop table if exists departments;

-- ============================================
-- 1) 基础表
-- ============================================
create table departments (
  id                bigserial primary key,
  dept_code         text not null unique,
  dept_name         text not null,
  parent_id         bigint references departments(id),
  status            text not null default 'active',
  created_at        timestamptz not null default now(),
  updated_at        timestamptz not null default now()
);

create table users (
  id                bigserial primary key,
  user_id           text not null unique, -- 对应 JWT sub
  username          text not null,
  email             text,
  dept_id           bigint references departments(id),
  status            text not null default 'active',
  created_at        timestamptz not null default now(),
  updated_at        timestamptz not null default now()
);

create table roles (
  id                bigserial primary key,
  role_code         text not null unique, -- viewer/developer/admin/...
  role_name         text not null,
  priority          int not null default 100,
  status            text not null default 'active',
  created_at        timestamptz not null default now(),
  updated_at        timestamptz not null default now()
);

create table user_roles (
  user_id           bigint not null references users(id) on delete cascade,
  role_id           bigint not null references roles(id) on delete cascade,
  expires_at        timestamptz,
  primary key (user_id, role_id)
);

-- ============================================
-- 2) 资源目录
-- ============================================
create table resources (
  id                bigserial primary key,
  resource_type     text not null check (resource_type in ('TOOL', 'KB', 'MCP_TOOL')),
  namespace         text not null default '*',
  kb_id             text,
  resource_key      text not null unique,
  attributes        jsonb not null default '{}'::jsonb,
  status            text not null default 'active',
  created_at        timestamptz not null default now(),
  updated_at        timestamptz not null default now()
);

-- ============================================
-- 3) 策略表（RBAC + ABAC）
-- ============================================
create table policies (
  id                bigserial primary key,
  policy_code       text not null unique,
  effect            text not null check (effect in ('ALLOW', 'DENY')),
  subject_type      text not null check (subject_type in ('USER', 'ROLE', 'DEPT', 'ALL')),
  subject_id        text not null, -- user_id / role_code / dept_code / *
  resource_type     text not null check (resource_type in ('TOOL', 'KB', 'MCP_TOOL', 'ALL')),
  namespace_pattern text not null default '*',
  resource_pattern  text not null default '*',
  action            text not null default '*', -- read/write/execute/search/admin/*
  condition_json    jsonb not null default '{}'::jsonb,
  priority          int not null default 1000, -- 数值越小优先级越高
  enabled           boolean not null default true,
  valid_from        timestamptz,
  valid_to          timestamptz,
  created_at        timestamptz not null default now(),
  updated_at        timestamptz not null default now()
);

-- ============================================
-- 4) 审计日志
-- ============================================
create table authz_audit_logs (
  id                 bigserial primary key,
  request_id         text,
  user_id            text,
  dept_code          text,
  roles              text[],
  tool_name          text,
  action             text,
  resource_key       text,
  decision           text not null check (decision in ('ALLOW', 'DENY')),
  matched_policy_id  bigint,
  reason_code        text,
  reason_message     text,
  context            jsonb not null default '{}'::jsonb,
  created_at         timestamptz not null default now()
);

-- ============================================
-- 5) 索引
-- ============================================
create index idx_users_user_id on users(user_id);
create index idx_users_dept_id on users(dept_id);

create index idx_roles_role_code on roles(role_code);
create index idx_user_roles_user on user_roles(user_id);
create index idx_user_roles_role on user_roles(role_id);

create index idx_resources_type_key on resources(resource_type, resource_key);
create index idx_resources_namespace_kb on resources(namespace, kb_id);

create index idx_policies_enabled_priority on policies(enabled, priority);
create index idx_policies_subject on policies(subject_type, subject_id);
create index idx_policies_resource on policies(resource_type, namespace_pattern, resource_pattern);
create index idx_policies_action on policies(action);
create index idx_policies_validity on policies(valid_from, valid_to);

create index idx_audit_created_at on authz_audit_logs(created_at desc);
create index idx_audit_user_id on authz_audit_logs(user_id);
create index idx_audit_decision on authz_audit_logs(decision);
```

## 6. 10 条样例策略数据（可直接执行）

> 说明：以下策略覆盖了 deny 优先、按角色授权、按部门授权、按用户特例、ABAC 条件控制等典型场景。

```sql
insert into policies (
  policy_code, effect, subject_type, subject_id, resource_type, namespace_pattern, resource_pattern, action, condition_json, priority, enabled
) values
-- 1) 全局 deny：viewer 禁用 bash
('P001_DENY_VIEWER_BASH', 'DENY', 'ROLE', 'viewer', 'TOOL', '*', 'tool:bash', 'execute', '{}'::jsonb, 10, true),

-- 2) 全局 deny：子代理禁止执行 bash（ABAC）
('P002_DENY_SUBAGENT_BASH', 'DENY', 'ALL', '*', 'TOOL', '*', 'tool:bash', 'execute',
 '{"require_subagent": false}'::jsonb, 15, true),

-- 3) allow：viewer 可读工具
('P003_ALLOW_VIEWER_READ_TOOLS', 'ALLOW', 'ROLE', 'viewer', 'TOOL', '*', 'tool:read_file', 'read', '{}'::jsonb, 100, true),

-- 4) allow：viewer 可搜索网页
('P004_ALLOW_VIEWER_WEB_SEARCH', 'ALLOW', 'ROLE', 'viewer', 'TOOL', '*', 'tool:web_search', 'search', '{}'::jsonb, 100, true),

-- 5) allow：developer 可写文件
('P005_ALLOW_DEVELOPER_WRITE', 'ALLOW', 'ROLE', 'developer', 'TOOL', '*', 'tool:write_file', 'write',
 '{"path_allow_prefixes":["/mnt/user-data/workspace/","/mnt/user-data/outputs/","./"]}'::jsonb, 80, true),

-- 6) allow：developer 可字符串替换
('P006_ALLOW_DEVELOPER_REPLACE', 'ALLOW', 'ROLE', 'developer', 'TOOL', '*', 'tool:str_replace', 'write',
 '{"path_allow_prefixes":["/mnt/user-data/workspace/","/mnt/user-data/outputs/","./"]}'::jsonb, 80, true),

-- 7) deny：ops 执行 bash 时屏蔽危险命令（ABAC）
('P007_DENY_OPS_DANGEROUS_BASH', 'DENY', 'ROLE', 'ops', 'TOOL', '*', 'tool:bash', 'execute',
 '{"bash_block_patterns":["rm -rf","sudo","shutdown","reboot","mkfs","dd if="]}'::jsonb, 20, true),

-- 8) allow：FIN 部门可查询财务知识库
('P008_ALLOW_FIN_KB_READ', 'ALLOW', 'DEPT', 'FIN', 'KB', 'corp.cn.finance', 'kb:corp.cn.finance:*', 'read', '{}'::jsonb, 60, true),

-- 9) deny：RND 部门禁止读财务知识库
```

## 7. JWT Claims 约定

建议令牌至少包含以下字段：

```json
{
  "sub": "u_fin_001",
  "dept": "FIN",
  "roles": ["viewer", "finance_editor"],
  "tenant": "corp.cn",
  "exp": 1893456000
}
```

映射建议：

- `sub` -> `users.user_id`
- `dept` -> `departments.dept_code`
- `roles[]` -> `roles.role_code`
- `tenant` -> `namespace` 前缀校验（可选）

## 8. MyGuardrailProvider 查询逻辑（实现指引）

## 8.1 输入上下文

- 从 JWT 取：`user_id/dept/roles`
- 从 `GuardrailRequest` 取：`tool_name/tool_input/thread_id/is_subagent`
- 解析目标：`action/resource_type/resource_key/namespace/kb_id`

## 8.2 判定流程

1. 查询候选策略（按 subject + resource + action + 生效时间）
2. 逐条执行 `condition_json`（ABAC）
3. 若命中 `DENY` -> 立即拒绝
4. 否则若命中 `ALLOW` -> 放行
5. 否则 -> 默认拒绝

参考伪流程：

```text
authorize(request):
  subject = parse_jwt_claims()
  target  = parse_resource(request.tool_name, request.tool_input)
  action  = parse_action(request.tool_name, request.tool_input)
  attrs   = build_context_attrs(request)

  candidates = query_enabled_policies(subject, target, action, now)
  matched = filter_by_abac_conditions(candidates, attrs, subject, target)

  if exists(matched where effect='DENY'):
      return DENY(first_by_priority)
  if exists(matched where effect='ALLOW'):
      return ALLOW(first_by_priority)
  return DENY(default)
```

## 9. condition_json 字段建议（ABAC）

建议从以下字段开始：

- `time_window`: 时间窗（例如 09:00-21:00）
- `require_subagent`: 是否允许子代理
- `bash_block_patterns`: 危险命令正则/关键字
- `path_allow_prefixes`: 允许写入路径前缀
- `dept_must_equal_namespace_segment`: 部门与 namespace 片段一致性检查

示例：

```json
{
  "time_window": {"start": "09:00", "end": "21:00", "tz": "Asia/Shanghai"},
  "require_subagent": false,
  "bash_block_patterns": ["rm -rf", "sudo", "shutdown"],
  "path_allow_prefixes": ["/mnt/user-data/workspace/", "/mnt/user-data/outputs/", "./"]
}
```

## 12. MyGuardrailProvider 首次联调 checklist（5分钟版）

目标：在最短时间内确认“策略查询 + deny 优先 + 审计落库”链路可用。

### Step 0：准备

- 已执行：`docs/sql/authz_init.sql`
- 已在 `config.yaml` 开启 guardrails，并指向 `MyGuardrailProvider`
- `MyGuardrailProvider` 已实现：
  - JWT claims 解析（`sub/dept/roles`）
  - 策略查询
  - `condition_json` 评估
  - 决策日志写入 `authz_audit_logs`

### Step 1：快速校验初始化数据（30 秒）

```sql
select count(*) as policy_count from policies;  -- 预期 >= 10
select count(*) as user_count from users;        -- 预期 >= 4
select count(*) as resource_count from resources;-- 预期 >= 10
```

### Step 2：准备 3 组测试身份（1 分钟）

建议在本地用三组 JWT（或 mock claims）：

- `viewer`：`sub=u_rnd_001, dept=RND, roles=[viewer]`
- `developer`：`sub=u_rnd_001, dept=RND, roles=[developer]`
- `admin`：`sub=u_admin_001, dept=HQ, roles=[admin]`

### Step 3：执行 4 条关键用例（2 分钟）

1. `viewer` 调用 `bash`
   - 预期：`DENY`
   - 命中策略：`P001_DENY_VIEWER_BASH`

2. `developer` 调用 `write_file` 写入 `./tmp.txt`
   - 预期：`ALLOW`
   - 命中策略：`P005_ALLOW_DEVELOPER_WRITE`

3. `viewer/dept=RND` 访问 `kb:corp.cn.finance:kb_invoice_001`
   - 预期：`DENY`
   - 命中策略：`P009_DENY_RND_FIN_KB`

4. `admin` 调用常规工具（如 `read_file`）
   - 预期：`ALLOW`
   - 命中策略：`P010_ALLOW_ADMIN_ALL`（若无更高优先级 deny）

### Step 4：审计日志核对（1 分钟）

```sql
select created_at, user_id, decision, resource_key, matched_policy_id, reason_code
from authz_audit_logs
order by id desc
limit 20;
```

核对点：

- 每次授权请求都有日志
- `DENY`/`ALLOW` 与预期一致
- `matched_policy_id` 非空（至少在命中策略时）
- `reason_code` 可解释（如 `rbac.tool_denied` / `oap.allowed`）

### Step 5：失败时最小排查（30 秒）

- 无日志：先看 Guardrail 是否挂载到 middleware 链
- 全部拒绝：先检查 JWT claims 映射是否正确（`sub/dept/roles`）
- 全部放行：检查默认分支是否为 `DENY`、是否误绕过了 provider
- 策略不命中：打印 `resource_key/action/namespace` 与策略字段对比

### 快速通过标准

满足以下 4 条即可认为“首次联调通过”：

- 能稳定复现至少 1 次 `DENY`
- 能稳定复现至少 1 次 `ALLOW`
- 审计日志有记录且可回溯到策略
- 同一请求重复执行结果一致（幂等）
