## 1. 执行摘要

### 1.1 核心结论

经过对 deer-flow 项目记忆系统的深入分析和企业版优化方案的全面评估,我们得出以下结论:

| 评估维度 | 评分 | 说明 |
|---------|------|------|
| **架构理念** | ⭐⭐⭐⭐⭐ | 分层架构+双轨召回设计先进,符合业界最佳实践 |
| **当前适配度** | ⭐⭐⭐ | 方案偏企业级,需针对当前单用户场景裁剪 |
| **实施难度** | ⭐⭐ | 全量实施需 2-3 周,分阶段可降低风险 |
| **投资回报率** | ⭐⭐⭐⭐⭐ | recall 配置可立竿见影提升推理质量 |

### 1.2 关键建议

1. **✅ 采纳核心理念**: 分层存储、可配置召回、双轨策略
2. **⚠️ 裁剪过度设计**: 暂不引入 Redis/L3/租户隔离
3. **🎯 分步实施**: recall 配置 → PG 存储 → 语义召回(可选)
4. **🔧 复用现有组件**: summarization/checkpoint 已解决部分问题

## 2. 现状分析

### 2.1 当前记忆架构

#### 2.1.1 存储层

```python
# 当前实现: FileMemoryStorage
# 位置: backend/packages/harness/deerflow/agents/memory/storage.py

class FileMemoryStorage(MemoryStorage):
    - 存储格式: JSON 文件 (memory.json)
    - 位置: .deer-flow/memory.json 或自定义路径
    - 缓存策略: 文件 mtime 检查 + 内存缓存
    - 并发支持: 单进程安全 (threading.Lock)
```

**优势**:
- ✅ 零依赖,开箱即用
- ✅ 便于调试和备份
- ✅ 适合单用户桌面场景

**局限**:
- ❌ 不支持多进程并发写入
- ❌ 无事务保证,崩溃可能丢数据
- ❌ 查询效率低 (全文件加载)
- ❌ 无法支持多租户

#### 2.1.2 写入管线

```
用户对话 → MemoryMiddleware.after_agent 
         → 过滤消息 (仅保留 human/ai)
         → 检测 correction/reinforcement 信号
         → 防抖入队 (30秒)
         → MemoryUpdater 调用 LLM
         → 解析 JSON 更新
         → FileMemoryStorage.save
```

**关键文件**:
- `memory_middleware.py`: 对话过滤和入队
- `queue.py`: 防抖队列,合并同线程更新
- `updater.py`: LLM 驱动的记忆合并
- `prompt.py`: MEMORY_UPDATE_PROMPT 模板

**特性**:
- ✅ LLM 智能提取,支持 6 类 facts
- ✅ 置信度评分 (0.0-1.0)
- ✅ correction/reinforcement 信号检测
- ✅ 去重和 max_facts 限制 (默认 100)
- ✅ 上传事件过滤 (避免持久化临时文件)

#### 2.1.3 注入机制

```python
# 位置: backend/packages/harness/deerflow/agents/lead_agent/prompt.py

def _get_memory_context(agent_name=None) -> str:
    memory_data = get_memory_data(agent_name)  # 加载全部记忆
    memory_content = format_memory_for_injection(
        memory_data, 
        max_tokens=2000  # token 预算
    )
    return f"<memory>{memory_content}</memory>"
```

**注入内容**:
1. **User Context**: workContext, personalContext, topOfMind
2. **History**: recentMonths, earlierContext, longTermBackground
3. **Facts**: 按置信度降序排列,直到 token 预算用尽

**问题**:
- ❌ **全量注入**: 不考虑与当前任务的相关性
- ❌ **低效使用 token**: 可能注入大量无关记忆
- ❌ **无优先级控制**: 仅靠置信度排序
- ❌ **不可配置**: 无法调节注入强度

#### 2.1.4 会话压缩 (Summarization)

```yaml
# config.yaml 配置
summarization:
  enabled: true
  trigger:
    - type: tokens
      value: 4000  # 超过 4000 tokens 触发
  keep:
    type: messages
    value: 20  # 保留最近 20 条消息
```

**工作机制**:
- 监控消息历史 token 数
- 超过阈值时触发压缩
- 保留最近消息 + 生成摘要
- 技能救援: 保护最近使用的 skill 文件

**与记忆的关系**:
- ✅ 压缩前通过 hook 将消息写入记忆队列
- ✅ 避免长期记忆重复存储会话细节
- ⚠️ 压缩后的摘要仅在当前会话可用

## 3. 方案评估

### 3.1 方案概述

企业版方案 ([记忆优化.md](./记忆优化.md)) 提出了以下核心设计:

```
┌─────────────────────────────────────────────────┐
│  L1: Prompt (活跃上下文)                         │
│  - 系统指令 + 最近对话                            │
│  - 经 recall 裁剪的长期记忆                       │
│  - 可选: pgvector 语义召回 Top-K                 │
└─────────────────────────────────────────────────┘
                      ↕
┌─────────────────────────────────────────────────┐
│  L2: Redis + PG (会话状态)                       │
│  - Redis: 键值缓存 (TTL)                         │
│  - PG memory_working: 持久化                     │
│  - 内容: 会话摘要、焦点、进度                     │
└─────────────────────────────────────────────────┘
                      ↕
┌─────────────────────────────────────────────────┐
│  L3: 向量归档 (本会话)                           │
│  - pgvector / Milvus                             │
│  - 内容: 早期对话片段、长文档切块                 │
│  - 按需检索,提升回 L1                            │
└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│  长期记忆 (双轨)                                 │
│  - PG memory_long_term: JSONB 权威               │
│  - PG pgvector: 语义索引 (辅助)                  │
└─────────────────────────────────────────────────┘
```

### 3.2 优点分析

#### 3.2.1 分层架构理念先进 ⭐⭐⭐⭐⭐

**CPU 缓存类比合理**:
- L1 (寄存器): 最小容量,最低延迟 → Prompt 注入
- L2 (L2 Cache): 中等容量,快速读写 → Redis + PG
- L3 (内存): 大容量,按需加载 → 向量归档

**优势**:
1. **解决核心矛盾**: 上下文窗口有限 vs 任务复杂度无限
2. **成本优化**: 仅将高价值信息放入 Prompt
3. **可扩展性**: 各层可独立优化和替换

#### 3.2.2 双轨记忆策略正确 ⭐⭐⭐⭐⭐

```
结构化 JSON (权威) + pgvector (语义召回)
```

**为什么正确**:
1. **避免反模式**: 不将向量数据库作为事实来源
2. **确定性 + 灵活性**: JSON 保证准确,向量提供相关性
3. **同源维护**: 向量从 JSON 派生,避免不一致
4. **降级安全**: 向量失败时,结构化注入仍可工作

#### 3.2.3 保留现有管线明智 ⭐⭐⭐⭐⭐

方案明确**不推翻**以下已验证组件:

| 组件 | 功能 | 评估 |
|------|------|------|
| `MemoryMiddleware` | 对话过滤和入队 | ✅ 稳定可靠 |
| `MemoryUpdateQueue` | 防抖合并 | ✅ 减少 LLM 调用 |
| `MemoryUpdater` | LLM 提取 | ✅ 智能准确 |
| `_apply_updates` | 事实合并去重 | ✅ 逻辑完善 |
| `format_memory_for_injection` | Token 计数 | ✅ 使用 tiktoken |
| correction/reinforcement | 信号检测 | ✅ 高质量特性 |

**优势**:
- ✅ 降低迁移风险
- ✅ 保护已有投资
- ✅ 团队学习成本低

#### 3.2.4 可配置召回策略实用 ⭐⭐⭐⭐⭐

```yaml
recall:
  max_facts_injection: 20          # 控制事实数量
  max_history_sections: 3          # 控制历史段数
  max_user_sections: 3             # 控制用户画像段数
  semantic_retrieval:
    enabled: false                 # 可选启用
    top_k: 5
    max_semantic_chars: 800
```

**价值**:
1. **企业分级**: 按成本/隐私调节"懂用户"强度
2. **可预测性**: 先按条数,再按 token 截断
3. **向后兼容**: 关闭时行为与现有一致

### 3.3 潜在问题

#### 3.3.1 过度设计风险 🔴 严重

**问题**: 方案引入过多组件

```
PostgreSQL + Redis + pgvector + L3 向量归档 + RLS + 租户隔离
     ↓
需要运维: 3 个数据库 + 消息队列 + worker 进程
```

**当前项目实际情况**:

| 需求 | 方案要求 | 实际需要 | 差距 |
|------|---------|---------|------|
| 存储 | PostgreSQL | 文件存储够用 | 过度 |
| 缓存 | Redis | 无高并发需求 | 过度 |
| 向量 | pgvector + L3 | 暂不需要 | 过度 |
| 权限 | RLS + 租户隔离 | 单用户 | 过度 |
| 异步 | 消息队列 | 同步够用 | 过度 |

**具体冲突**:

1. **已有 SummarizationMiddleware**
   - 已处理会话压缩
   - 已保留最近 20 条消息
   - 已实现技能救援
   - L2 与之功能重叠

2. **已有 LangGraph Checkpoint**
   - 已持久化会话状态 (SQLite/PG)
   - 已支持状态恢复
   - L2/L3 与之功能重叠

3. **无多租户需求**
   - 代码中无 `tenant_id` 概念
   - 无网关鉴权层
   - 单用户桌面应用模式

**建议**:
```
分阶段实施,避免一次性引入所有组件:
阶段 1: recall 配置 (1 天) → 解决注入效率
阶段 2: PostgreSQL 存储 (3 天) → 解决并发/备份
阶段 3: TF-IDF 语义召回 (2 天) → 提升相关性
阶段 4: pgvector (可选, 5 天) → 企业级需求
```

#### 3.3.2 工作记忆 L2 定位不清 🟡 中等

**方案描述**:
> L2: Redis 键值 + PG 持久化,存储会话摘要、焦点、进度

**实际问题**:

1. **与 Summarization 重叠**
   ```python
   # 已有: summarization_middleware.py
   - 触发: 4000 tokens 或 50 条消息
   - 保留: 最近 20 条消息
   - 生成: 会话摘要 (HumanMessage)
   ```

2. **与 Checkpoint 重叠**
   ```
   已有: .deer-flow/checkpoints.db (SQLite)
   - 自动保存 thread 状态
   - 支持状态恢复
   - 包含完整消息历史
   ```

3. **写入来源不明**
   - 方案 A: 扩展 LLM 输出,一次写两表
   - 方案 B: 独立任务按轮次更新
   - 未明确与现有管线的集成点

**建议**:
```python
# 方案: 复用 summarization hook,不引入独立 L2
# 文件: summarization_hook.py

def memory_flush_hook(context):
    """压缩前将消息写入记忆队列 (已有)"""
    # 新增: 将生成的 summary 也存入 PG
    session_summary = {
        "thread_id": context.thread_id,
        "summary": generated_summary,
        "focus": extract_focus(context.messages),
        "updated_at": now()
    }
    
    # 写入 memory_working 表
    await pg_pool.execute(
        "INSERT INTO memory_working ...",
        session_summary
    )
```

**优势**:
- ✅ 零额外复杂度
- ✅ 与现有流程对齐
- ✅ 摘要跨会话可用

#### 3.3.3 L3 会话归档职责模糊 🟡 中等

**方案描述**:
> L3: 本会话向量归档,存储更早轮次的详细对话片段

**问题**:

1. **与 summarization 冲突**
   - 被压缩的消息已经丢失
   - 除非在压缩前归档,但这增加复杂度

2. **与 checkpoint 重叠**
   - LangGraph 已保存完整历史
   - 可直接从 checkpoint 恢复

3. **检索时机不明**
   - 自动注入? → 成本高
   - Agent 主动调用? → 需定义工具
   - 用户触发? → 需 UI 支持

**使用场景分析**:

| 场景 | 是否需要 L3 | 现有方案 |
|------|------------|---------|
| 用户问"之前讨论过 X 吗?" | ✅ 需要 | ❌ 不支持 |
| 长任务 (>100 轮) 回顾细节 | ✅ 需要 | ❌ 不支持 |
| 普通对话 | ❌ 不需要 | ✅ summarization 够用 |

**建议**:
```
明确 L3 定位:
1. 作为 MCP 工具提供,Agent 按需调用
2. 不在每次推理时自动检索 (成本高)
3. 仅当用户明确询问或 Agent 判断需要时触发

实现策略:
- 工具名: memory_search
- 输入: query (用户问题)
- 输出: Top-K 相关片段
- 触发: Agent 自主决定或用户指令
```

#### 3.3.4 权限横切过度设计 🔴 严重

**方案要求**:
```
tenant_id + subject + RLS + 网关鉴权 + 最小权限库账号
```

**当前项目**:
- ❌ 无网关层,直接 FastAPI 暴露
- ❌ 无身份认证 (可选,但未启用)
- ❌ 单用户桌面应用模式

**RLS (Row Level Security) 复杂度**:
```sql
-- 方案要求

CREATE POLICY tenant_isolation ON memory_long_term
  USING (tenant_id = current_setting('app.tenant_id'));

-- 需要在每次查询前设置

```

**建议**:
```

- 跳过租户隔离
- 用 agent_name 隔离即可 (已支持)

企业版 (未来):
- 先实现简单 API Key 认证
- 再考虑 RLS
- 避免"为未来需求过度设计"
```

#### 3.3.5 向量索引更新策略复杂 🟡 中等

**方案描述**:
```
save 成功后 → 同步/异步更新 pgvector
异步推荐: 入队 → worker 拉取 → diff 或全量重建
```

**实际复杂度**:

1. **需要消息队列**
   - RabbitMQ / Celery / Redis Streams?
   - 增加运维负担

2. **需要 worker 进程**
   - 独立的 embedding worker
   - 需要监控和重启机制

3. **diff 算法复杂**
   - JSONB 变化检测
   - 增量更新 vs 全量重建
   - 版本对齐问题

**建议**:
```python
# 简化方案: 同步写入 + 异步 embedding (无需消息队列)

class PostgresMemoryStorage(MemoryStorage):
    async def save(self, memory_data, agent_name=None):
        # 1. 事务写入 PG
        async with self.pool.transaction():
            await self.pool.execute(
                "INSERT INTO memory_long_term ...",
                memory_data
            )
        
        # 2. 异步触发 embedding (不阻塞)
        threading.Thread(
            target=self._update_embeddings,
            args=(memory_data, agent_name),
            daemon=True
        ).start()
        
        return True
    
    def _update_embeddings(self, memory_data, agent_name):
        """后台线程更新向量索引"""
        # 提取可嵌入文本
        chunks = self._extract_chunks(memory_data)
        
        # 调用 embedding 模型
        embeddings = openai.embeddings.create(
            model="text-embedding-3-small",
            input=[c['text'] for c in chunks]
        )
        
        # UPSERT 到向量表
        for chunk, embedding in zip(chunks, embeddings):
            self.pool.execute(
                "INSERT INTO memory_long_term_embedding ...",
                chunk, embedding
            )

# 优势:
# - 无需消息队列
# - 单机够用
# - 失败不影响主流程
# 
# 劣势:
# - 高并发时线程过多 (但当前项目不需要)
```

## 4. 定制化实施方案

### 4.1 实施原则

1. **最小改动**: 保留现有管线,仅替换必要组件
2. **分步实施**: 每步可独立验证,降低风险
3. **向后兼容**: 关闭新特性时行为与现有一致
4. **配置驱动**: 通过 config.yaml 控制新特性开关

### 4.2 阶段 1: 实现 recall 配置 (P0 - 立即实施)

**目标**: 解决全量注入导致的 token 浪费问题

**预期效果**: 减少 60% 无用记忆注入,提升推理质量

#### 4.2.1 配置扩展

```yaml
# config.yaml - 新增 recall 段
memory:
  enabled: true
  injection_enabled: true
  max_injection_tokens: 2000
  max_facts: 100
  fact_confidence_threshold: 0.7
  debounce_seconds: 30
  model_name: null
  storage_class: deerflow.agents.memory.storage.FileMemoryStorage

  # ===== 新增: 召回配置 =====
  recall:
    # Facts 注入限制
    max_facts_injection: 20  # 最多注入 20 条 facts (0=不限制)
    
    # History 注入限制
    max_history_sections: 3  # 最多注入 3 段历史 (recentMonths → earlierContext → longTermBackground)
    
    # User Context 注入限制
    max_user_sections: 3     # 最多注入 3 段用户画像 (workContext → personalContext → topOfMind)
    
    # 语义召回 (可选,阶段 3 实现)

      top_k: 5
      max_semantic_chars: 800
```

#### 4.2.2 代码实现

**步骤 1: 扩展 MemoryConfig**

```python
# 文件: backend/packages/harness/deerflow/config/memory_config.py

from pydantic import BaseModel, Field

class SemanticRetrievalConfig(BaseModel):
    """语义召回配置"""
```

```python
# 文件: backend/packages/harness/deerflow/agents/memory/prompt.py

from deerflow.config.memory_config import get_memory_config, RecallConfig

def format_memory_for_injection(
    memory_data: dict[str, Any], 
    max_tokens: int = 2000,
    recall_config: RecallConfig | None = None
) -> str:
    """Format memory data for injection into system prompt.
    
    Args:
        memory_data: The memory data dictionary.
        max_tokens: Maximum tokens to use.
        recall_config: Recall configuration (uses global config if None).
    
    Returns:
        Formatted memory string for system prompt injection.
    """
    if not memory_data:
        return ""
    
    # 使用全局配置或传入配置
    if recall_config is None:
        recall_config = get_memory_config().recall
    
    sections = []
    
    # ===== 1. User Context (按段数限制) =====
    user_data = memory_data.get("user", {})
    if user_data:
        user_sections = []
        section_count = 0
        
        # workContext
        if section_count < recall_config.max_user_sections:
            work_ctx = user_data.get("workContext", {})
            if work_ctx.get("summary"):
                user_sections.append(f"Work: {work_ctx['summary']}")
                section_count += 1
        
        # personalContext
        if section_count < recall_config.max_user_sections:
            personal_ctx = user_data.get("personalContext", {})
            if personal_ctx.get("summary"):
                user_sections.append(f"Personal: {personal_ctx['summary']}")
                section_count += 1
        
        # topOfMind
        if section_count < recall_config.max_user_sections:
            top_of_mind = user_data.get("topOfMind", {})
            if top_of_mind.get("summary"):
                user_sections.append(f"Current Focus: {top_of_mind['summary']}")
                section_count += 1
        
        if user_sections:
            sections.append("User Context:\n" + "\n".join(f"- {s}" for s in user_sections))
    
    # ===== 2. History (按段数限制) =====
    history_data = memory_data.get("history", {})
    if history_data:
        history_sections = []
        section_count = 0
        
        # recentMonths
        if section_count < recall_config.max_history_sections:
            recent = history_data.get("recentMonths", {})
            if recent.get("summary"):
                history_sections.append(f"Recent: {recent['summary']}")
                section_count += 1
        
        # earlierContext
        if section_count < recall_config.max_history_sections:
            earlier = history_data.get("earlierContext", {})
            if earlier.get("summary"):
                history_sections.append(f"Earlier: {earlier['summary']}")
                section_count += 1
        
        # longTermBackground
        if section_count < recall_config.max_history_sections:
            background = history_data.get("longTermBackground", {})
            if background.get("summary"):
                history_sections.append(f"Background: {background['summary']}")
                section_count += 1
        
        if history_sections:
            sections.append("History:\n" + "\n".join(f"- {s}" for s in history_sections))
    
    # ===== 3. Facts (按条数 + 置信度排序) =====
    facts_data = memory_data.get("facts", [])
    if isinstance(facts_data, list) and facts_data:
        # 按置信度降序
        ranked_facts = sorted(
            (f for f in facts_data if isinstance(f, dict) and isinstance(f.get("content"), str) and f.get("content").strip()),
            key=lambda fact: _coerce_confidence(fact.get("confidence"), default=0.0),
            reverse=True,
        )
        
        # 限制条数
        if recall_config.max_facts_injection > 0:
            ranked_facts = ranked_facts[:recall_config.max_facts_injection]
        
        # Token 预算控制
        base_text = "\n\n".join(sections)
        base_tokens = _count_tokens(base_text) if base_text else 0
        facts_header = "Facts:\n"
        separator_tokens = _count_tokens("\n\n" + facts_header) if base_text else _count_tokens(facts_header)
        running_tokens = base_tokens + separator_tokens
        
        fact_lines: list[str] = []
        for fact in ranked_facts:
            content_value = fact.get("content")
            if not isinstance(content_value, str):
                continue
            content = content_value.strip()
            if not content:
                continue
            
            category = str(fact.get("category", "context")).strip() or "context"
            confidence = _coerce_confidence(fact.get("confidence"), default=0.0)
            source_error = fact.get("sourceError")
            
            if category == "correction" and isinstance(source_error, str) and source_error.strip():
                line = f"- [{category} | {confidence:.2f}] {content} (avoid: {source_error.strip()})"
            else:
                line = f"- [{category} | {confidence:.2f}] {content}"
            
            line_text = ("\n" + line) if fact_lines else line
            line_tokens = _count_tokens(line_text)
            
            if running_tokens + line_tokens <= max_tokens:
                fact_lines.append(line)
                running_tokens += line_tokens
            else:
                break
        
        if fact_lines:
            sections.append("Facts:\n" + "\n".join(fact_lines))
    
    # ===== 4. 最终 token 截断 =====
    if not sections:
        return ""
    
    result = "\n\n".join(sections)
    token_count = _count_tokens(result)
    
    if token_count > max_tokens:
        char_per_token = len(result) / token_count
        target_chars = int(max_tokens * char_per_token * 0.95)
        result = result[:target_chars] + "\n..."
    
    return result
```

```python
# 文件: backend/packages/harness/deerflow/agents/memory/postgres_storage.py

import asyncio
import logging
from typing import Any

try:
    import asyncpg
except ImportError:
    asyncpg = None

from deerflow.agents.memory.storage import MemoryStorage, create_empty_memory
from deerflow.config.memory_config import get_memory_config

logger = logging.getLogger(__name__)

class PostgresMemoryStorage(MemoryStorage):
    """PostgreSQL-based memory storage provider."""
    
    def __init__(self):
        """Initialize the PostgreSQL memory storage."""
        if asyncpg is None:
            raise ImportError(
                "asyncpg is required for PostgresMemoryStorage. "
                "Install it with: uv add asyncpg"
            )
        
        self._pool: asyncpg.Pool | None = None
        self._lock = asyncio.Lock()
    
    async def _get_pool(self) -> asyncpg.Pool:
        """Get or create connection pool."""
        if self._pool is not None:
            return self._pool
        
        async with self._lock:
            if self._pool is not None:
                return self._pool
            
            config = get_memory_config()
            database_url = config.storage_path or "postgresql://localhost/deerflow"
            
            self._pool = await asyncpg.create_pool(
                dsn=database_url,
                min_size=2,
                max_size=10,
                command_timeout=60
            )
            
            logger.info("PostgreSQL memory storage pool created")
            return self._pool
    
    async def load(self, agent_name: str | None = None) -> dict[str, Any]:
        """Load memory data from PostgreSQL."""
        pool = await self._get_pool()
        
        async with pool.acquire() as conn:
            row = await conn.fetchrow(
                """
                SELECT payload FROM memory_long_term 
                WHERE agent_name IS NOT DISTINCT FROM $1
                """,
                agent_name
            )
            
            if row is None:
                return create_empty_memory()
            
            return row["payload"]
    
    async def reload(self, agent_name: str | None = None) -> dict[str, Any]:
        """Force reload memory data (same as load for PG)."""
        return await self.load(agent_name)
    
    async def save(self, memory_data: dict[str, Any], agent_name: str | None = None) -> bool:
        """Save memory data to PostgreSQL."""
        try:
            pool = await self._get_pool()
            
            async with pool.acquire() as conn:
                async with conn.transaction():
                    # UPSERT: INSERT ... ON CONFLICT DO UPDATE
                    await conn.execute(
                        """
                        INSERT INTO memory_long_term (agent_name, payload, version, updated_at)
                        VALUES ($1, $2, 1, NOW())
                        ON CONFLICT (agent_name)
                        DO UPDATE SET 
                            payload = $2,
                            version = memory_long_term.version + 1,
                            updated_at = NOW()
                        """,
                        agent_name,
                        memory_data
                    )
            
            logger.info("Memory saved to PostgreSQL (agent=%s)", agent_name)
            return True
            
        except Exception as e:
            logger.error("Failed to save memory to PostgreSQL: %s", e)
            return False
    
    async def close(self):
        """Close connection pool."""
        if self._pool is not None:
            await self._pool.close()
            self._pool = None
            logger.info("PostgreSQL memory storage pool closed")

# 同步包装器 (适配现有接口)
class SyncPostgresMemoryStorage(MemoryStorage):
    """Synchronous wrapper for PostgresMemoryStorage."""
    
    def __init__(self):
        self._async_storage = PostgresMemoryStorage()
    
    def load(self, agent_name: str | None = None) -> dict[str, Any]:
        """Load memory data (sync)."""
        return asyncio.run(self._async_storage.load(agent_name))
    
    def reload(self, agent_name: str | None = None) -> dict[str, Any]:
        """Reload memory data (sync)."""
        return asyncio.run(self._async_storage.reload(agent_name))
    
    def save(self, memory_data: dict[str, Any], agent_name: str | None = None) -> bool:
        """Save memory data (sync)."""
        return asyncio.run(self._async_storage.save(memory_data, agent_name))
```

**目标**: 提升记忆注入的相关性,不依赖外部服务

#### 4.4.1 实现方案

```python
# 文件: backend/packages/harness/deerflow/agents/memory/semantic_recall.py

try:
    from sklearn.feature_extraction.text import TfidfVectorizer
    from sklearn.metrics.pairwise import cosine_similarity
    SKLEARN_AVAILABLE = True
except ImportError:
    SKLEARN_AVAILABLE = False

def tfidf_semantic_recall(
    query: str,
    facts: list[dict],
    top_k: int = 5
) -> list[dict]:
    """使用 TF-IDF 进行语义召回.
    
    Args:
        query: 查询文本 (最近用户消息)
        facts: 事实列表
        top_k: 返回 Top-K 结果
    
    Returns:
        排序后的事实列表
    """
    if not SKLEARN_AVAILABLE:
        # 降级: 按置信度排序
        return sorted(facts, key=lambda f: f.get("confidence", 0), reverse=True)[:top_k]
    
    if not facts or not query.strip():
        return facts[:top_k]
    
    # 提取事实文本
    fact_texts = [f["content"] for f in facts if f.get("content")]
    
    if not fact_texts:
        return facts[:top_k]
    
    # TF-IDF 向量化
    vectorizer = TfidfVectorizer()
    tfidf_matrix = vectorizer.fit_transform(fact_texts + [query])
    
    # 计算相似度
    query_vector = tfidf_matrix[-1:]
    fact_vectors = tfidf_matrix[:-1]
    similarities = cosine_similarity(query_vector, fact_vectors)[0]
    
    # 排序并返回 Top-K
    top_indices = similarities.argsort()[-top_k:][::-1]
    return [facts[i] for i in top_indices]
```

```python
# 文件: backend/packages/harness/deerflow/agents/memory/embedding_updater.py

import threading
import logging
from typing import Any

try:
    import openai
except ImportError:
    openai = None

logger = logging.getLogger(__name__)

class EmbeddingUpdater:
    """异步更新向量索引."""
    
    def __init__(self, model: str = "text-embedding-3-small"):
        if openai is None:
            raise ImportError("openai is required for EmbeddingUpdater")
        
        self.model = model
    
    def extract_chunks(self, memory_data: dict[str, Any]) -> list[dict]:
        """从记忆数据中提取可嵌入文本块."""
        chunks = []
        
        # 1. 摘要段落
        for section in ["user", "history"]:
            section_data = memory_data.get(section, {})
            for key, val in section_data.items():
                if isinstance(val, dict) and val.get("summary"):
                    chunks.append({
                        "source_kind": "summary",
                        "ref": f"{section}.{key}",
                        "content_text": val["summary"]
                    })
        
        # 2. Facts
        for fact in memory_data.get("facts", []):
            if fact.get("content"):
                chunks.append({
                    "source_kind": "fact",
                    "ref": fact["id"],
                    "content_text": fact["content"]
                })
        
        return chunks
    
    def update_async(self, memory_data: dict[str, Any], agent_name: str | None):
        """后台更新向量索引."""
        thread = threading.Thread(
            target=self._update,
            args=(memory_data, agent_name),
            daemon=True
        )
        thread.start()
    
    def _update(self, memory_data: dict[str, Any], agent_name: str | None):
        """实际更新逻辑."""
        try:
            # 1. 提取文本块
            chunks = self.extract_chunks(memory_data)
            
            if not chunks:
                return
            
            # 2. 调用 embedding 模型
            response = openai.embeddings.create(
                model=self.model,
                input=[c["content_text"] for c in chunks]
            )
            
            # 3. UPSERT 到向量表
            from deerflow.agents.memory.postgres_storage import PostgresMemoryStorage
            storage = PostgresMemoryStorage()
            pool = asyncio.run(storage._get_pool())
            
            async with pool.acquire() as conn:
                for chunk, embedding_obj in zip(chunks, response.data):
                    await conn.execute(
                        """
                        INSERT INTO memory_long_term_embedding 
                        (agent_name, source_kind, ref, content_text, embedding)
                        VALUES ($1, $2, $3, $4, $5)
                        ON CONFLICT (chunk_id)
                        DO UPDATE SET 
                            content_text = $4,
                            embedding = $5,
                            updated_at = NOW()
                        """,
                        agent_name,
                        chunk["source_kind"],
                        chunk["ref"],
                        chunk["content_text"],
                        embedding_obj.embedding
                    )
            
            logger.info("Updated %d embeddings for agent=%s", len(chunks), agent_name)
            
        except Exception as e:
            logger.error("Failed to update embeddings: %s", e)
```

#### 4.5.3 语义召回查询

```python
# 文件: backend/packages/harness/deerflow/agents/memory/pgvector_recall.py

async def pgvector_semantic_recall(
    query: str,
    agent_name: str | None,
    top_k: int = 5,
    max_chars: int = 800
) -> list[str]:
    """使用 pgvector 进行语义召回.
    
    Args:
        query: 查询文本
        agent_name: Agent 名称
        top_k: 返回 Top-K
        max_chars: 最大字符数
    
    Returns:
        命中的文本片段列表
    """
    from deerflow.agents.memory.postgres_storage import PostgresMemoryStorage
    
    storage = PostgresMemoryStorage()
    pool = await storage._get_pool()
    
    async with pool.acquire() as conn:
        # 1. 获取 query 的 embedding
        response = openai.embeddings.create(
            model="text-embedding-3-small",
            input=[query]
        )
        query_embedding = response.data[0].embedding
        
        # 2. 相似度查询
        rows = await conn.fetch(
            """
            SELECT content_text, source_kind, ref
            FROM memory_long_term_embedding
            WHERE agent_name IS NOT DISTINCT FROM $1
            ORDER BY embedding <=> $2
            LIMIT $3
            """,
            agent_name,
            query_embedding,
            top_k
        )
        
        # 3. 截断到字符预算
        results = []
        total_chars = 0
        
        for row in rows:
            text = row["content_text"]
            if total_chars + len(text) <= max_chars:
                results.append(text)
                total_chars += len(text)
            else:
                # 截断最后一条
                remaining = max_chars - total_chars
                if remaining > 50:  # 至少保留 50 字符
                    results.append(text[:remaining] + "...")
                break
        
        return results
```

#### 5.1.2 推理质量提升

**场景 1: 代码开发**
```
用户: "帮我优化这个数据库查询"

当前注入:
- 全部 100 条 facts (包含无关信息)
- 如: "用户喜欢 Python", "用户住在上海"

阶段 1 后注入:
- Top 20 facts (按置信度)
- 如: "项目使用 PostgreSQL", "查询性能是关键"

阶段 3 后注入:
- TF-IDF 召回相关 facts
- 如: "SQL 查询优化经验", "慢查询分析方法"
```

**场景 2: 跨会话任务**
```
会话 1: "我需要分析销售数据"
会话 2 (3 天后): "继续之前的分析"

当前:
- 从 memory.json 加载全部记忆
- 可能包含 50+ 无关 facts

阶段 2 后:
- PostgreSQL 事务保证
- 不会因崩溃丢失记忆

阶段 4 后:
- pgvector 召回会话 1 相关内容
- 精准注入销售分析相关记忆
```

### 5.2 风险点

#### 5.2.1 技术风险

| 风险 | 影响 | 概率 | 缓解措施 |

| PostgreSQL 单点故障 | 记忆丢失 | 低 | 定期备份 + 降级到文件 |
| TF-IDF 效果差 | 召回不相关 | 中 | 保留置信度降级 |
| pgvector 成本高 | API 费用增加 | 中 | 配置开关 + 限额 |
| 迁移数据丢失 | 记忆丢失 | 低 | 迁移前备份 JSON |
